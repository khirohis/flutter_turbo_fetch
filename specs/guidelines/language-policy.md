# 言語運用ポリシー（`language-policy.md`）

本ドキュメントは、`flutter_turbo_fetch` における **「制御系（AI への指示・内部仕様・進行管理）」** と **「成果物系（対外ドキュメント・コード・テスト）」** の言語分離ルールを規定する。

---

## 1. 基本原則

1. **AI への指示・内部仕様・ユーザー対話: 日本語**
   - ユーザーとのチャット対話、設計ディスカッション、進捗確認、レビュー依頼はすべて **日本語** で行う。
   - 内部仕様書・設計定義・ロードマップ（`specs/` 配下）は、ニュアンスの欠落を防ぎ設計精度を高めるため **日本語** を正本とする。
2. **対外向けドキュメント・ソースコード・テスト: 英語（US English）**
   - 公開ドキュメント（`docs/`、`README.md`、`CHANGELOG.md`）、プロダクションコード、テストコード、Git コミットメッセージはすべて **英語（US English）** で統一する。

---

## 2. ディレクトリ・成果物別の言語規定一覧

| カテゴリ | 対象パス / 成果物 | 正本言語 | 役割・対象読者 |
| :--- | :--- | :---: | :--- |
| **ユーザー対話** | チャット・ディスカッション | **日本語** | メンテナー ↔ AI 間の意思決定・思考精度の担保 |
| **AI 起点ルール** | `AGENTS.md` | **日本語** | AI エージェントが最初に読み込む最優先ルール |
| **内部仕様・管理** | `specs/**/*.md` | **日本語** | AI・メンテナー向け仕様境界、開発規約、ロードマップ |
| **対外ドキュメント** | `docs/**/*.md` | **英語** | 利用者向け設計根拠、リファレンス実装、ベンチマーク実測レポート |
| **公開パッケージ情報** | `README.md` / `CHANGELOG.md` / `pubspec.yaml` | **英語** | `pub.dev` および GitHub トップの導入・利用ガイド |
| **ソースコード** | `lib/**` / `android/**` / `darwin/**` / `windows/**` / `linux/**` / `pigeons/**` | **英語** | 識別子、Doc コメント（DartDoc / KDoc / SwiftDoc / Doxygen）、インラインコメント |
| **テスト・サンプル** | `test/**` / `example/**` / 各 OS ネイティブテスト | **英語** | テストケース名、アサーションメッセージ、UI 表示文言、コメント |
| **バージョン管理** | Git コミットメッセージ、PR 概要 | **英語** | Conventional Commits（`feat:`, `fix:`, `refactor:`, `docs:`, `test:`, `chore:` 等） |

---

## 3. 英語コーディング & ドキュメント規約

- **文体・トーン**: 簡潔・明瞭・技術的。能動態を基本とし、各プラットフォーム標準の技術用語を使用する。
- **スペル**: 米国英語（US English: `behavior`, `synchronize`, `canceled` 等）。
- **コードコメントの原則**: コードを見れば自明な内容（What）は書かず、**設計理由・制約事項・メモリ所有権・スレッド安全性（Why / Invariant）** に絞って記述する。
