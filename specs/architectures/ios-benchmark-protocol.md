# iOS 実機ベンチマークの公開条件

## 既存計測の監査

- `fetch()` と `transformResponse()` の境界はストリーミング方式とネイティブ一括受信方式で異なる。既存 Net / Parse 値を同一フェーズの比較として掲載しない。
- 未取得の計測、全失敗時の統計、RSS 取得例外、フレーム未取得はゼロに置換せず N/A とする。
- 現行スイートは各シナリオで固定順の1試行であり、各試行内部の10周は独立した10試行ではない。

## 新しい測定プロトコル

- ライブラリ本体は変更しない。専用の example エントリポイントを使い、Release 実機以外の結果を本番データに混ぜない。
- A/B/C それぞれで各方式を1試行ウォームアップし、続いて10試行ずつ測定する。各試行は既存の90/100/100件のスイープと同じ。方式順は試行ごとに循環する。ウォームアップと本測定は区別して保存する。
- 各方式・シナリオのクライアントはウォームアップと本測定で再利用し、接続プールを温める。サーバーの全サイズのJSONも事前生成する。
- Network は Dio 呼出開始から本文バイト列全体の取得まで。Parse は取得済み本文に対するプリセット既定トランスフォーマーの実行時間。共通の本文取得境界を導入した分割計測であり、既存の通常パイプラインそのものの性能値とは区別する。
- 全方式で同じ JSON を全件デコードし、サイズ指定・件数・アイテム数の整合性を検証する。独自モデルへのマッピングは行わない。
- リクエストごとにステータス、本文長、サーバーの `x-http-version`、Network / Parse / 全体時間、失敗理由の分類を保存する。方式名からHTTPバージョンを推測しない。
- 方式間で実本文長が一致すること、IO は1.1・他2方式は2.0であることを集計時に検証する。
- フレーム計測は本計測では N/A とし、必要時に別の Profile 実行で収集する。RSS は25ms間隔のサンプリング値で、真の最大値を保証しない。計測不能時は null とする。
- 各試行のTotal、RPS、Network / Parse の平均・P50・P95、成功/失敗、サンプリングRSSを集計する。試行間の平均・中央値・標準偏差・最小・最大を掲載する。
- 単一のLANアドレスのみでTLSサーバーを待ち受ける。SAN に実接続先を含める。ローカル自己署名検証の緩和を使う場合は全方式で同じ条件にし、明記する。
- 公開CSVとレポートには端末ID、ユーザー名、LANアドレス、鍵、証明書、署名情報を含めない。収集用APIは有効化したときだけ使えるものとし、入力上限と保存先を制限する。

## 公開ゲート

- 未ペアリング等で実機測定できない場合、実測CSVにデータ行を作らず、レポートに未実施と明記する。Simulatorやホストテストの値をiOS実機結果に転用しない。
- 不完全な資料は Draft PR とし、速度向上や優位性を主張しない。
